# FlurAI - Система анализа флюорографии

Современное desktop-приложение для анализа флюорографических снимков с ролевой системой доступа.

## 🚀 Возможности

### Для врачей-рентгенологов:
- 📸 Загрузка и анализ медицинских снимков
- 👥 Управление пациентами
- 📊 Персональная статистика и история исследований
- ⚙️ Настройки рабочего места

### Для администраторов:
- 👨‍⚕️ Управление врачами и их правами доступа
- 📈 Аналитика и отчеты по работе отделения
- 📊 Мониторинг активности врачей
- ⚙️ Настройки системы и интеграций

## 🛠 Технический стек

- **Python 3.8+** - основной язык программирования
- **CustomTkinter** - современный UI фреймворк
- **PIL/Pillow** - работа с медицинскими изображениями
- **OpenCV** - обработка изображений
- **Matplotlib/Plotly** - визуализация данных
- **SQLite** - локальная база данных

## 📦 Установка

1. **Клонирование репозитория:**
```bash
git clone <repository-url>
cd FlurAI
```

2. **Установка зависимостей:**
```bash
# Минимальная установка (рекомендуется)
pip install -r requirements-minimal.txt

# Или полная установка
pip install -r requirements.txt
```

3. **Запуск backend API (FastAPI + SQLite):**
```bash
cd ../backend
pip install -r requirements.txt
uvicorn backend.app:app --reload --port 8000
```

4. **Запуск desktop-приложения:**
```bash
python main.py
```

## 🔗 Интеграция с backend

- Desktop-клиент обращается к FastAPI backend (`backend/app.py`) через модуль `services/api_client.py`.
- По умолчанию используется адрес `http://127.0.0.1:8000`. Его можно изменить с помощью переменной окружения `FLURO_BACKEND_URL`.
- На экраны врача подтягиваются реальные данные по пациентам, исследованиям и алертам из API `/patients`, `/dashboard/*`, `/analysis/*`.
- Перед запуском фронтенда убедитесь, что backend поднят и база данных инициализирована (создается автоматически при первом старте).

## 🌐 Черновик REST API

Базовый URL: `/api/v1`. Все ответы в формате JSON, аутентификация через `Authorization: Bearer <token>`. Везде, где не указано иначе, успешный ответ возвращает поле `success: true`, а ошибки — объект `error` с кодом и сообщением.

### Аутентификация
| Метод | Путь | Описание | Тело запроса | Успешный ответ |
| --- | --- | --- | --- | --- |
| POST | `/auth/login` | Выдача JWT токена для врача или администратора | `{"username": "doctor","password": "123"}` | `{"token": "...","role": "doctor","expires_in": 3600}` |
| POST | `/auth/refresh` | Обновление токена по refresh-токену | `{"refresh_token": "..."}` | `{"token": "...","refresh_token": "...","expires_in": 3600}` |
| POST | `/auth/logout` | Отзыв refresh-токена | `{"refresh_token": "..."}` | `204 No Content` |

### Пользователи и роли
| Метод | Путь | Описание | Тело запроса | Примечание |
| --- | --- | --- | --- | --- |
| GET | `/users` | Список врачей с фильтрами | query `role`, `status` | Только администратор |
| POST | `/users` | Создание врача/админа | `{"email": "...","role": "doctor","license_id": "..."}` | Ответ `201` с объектом пользователя |
| PATCH | `/users/{user_id}` | Обновление профиля или прав | Частичный JSON | Валидация ролей |
| DELETE | `/users/{user_id}` | Деактивация пользователя | — | Мягкое удаление |

### Пациенты
| Метод | Путь | Описание | Тело / query | Ответ |
| --- | --- | --- | --- | --- |
| GET | `/patients` | Поиск пациентов | query `q`, `page`, `doctor_id` | Пагинированный список |
| POST | `/patients` | Создание карточки пациента | `{"full_name": "...","birth_date": "...","policy": "..."}` | `201` + объект |
| GET | `/patients/{patient_id}` | Карточка пациента | — | Полный профиль + последние исследования |
| PATCH | `/patients/{patient_id}` | Обновление данных | Частичный JSON | Возвращает обновлённый профиль |

### Исследования и снимки
| Метод | Путь | Описание | Тело / headers | Ответ |
| --- | --- | --- | --- | --- |
| GET | `/studies` | Лента исследований | query `patient_id`, `urgent`, `status` | Пагиация + сортировка |
| POST | `/studies` | Создание исследования | `{"patient_id": "...","priority": "normal"}` | `201` + идентификатор |
| GET | `/studies/{study_id}` | Детали исследования | — | Полный объект + заключение |
| POST | `/studies/{study_id}/images` | Загрузка флюорограммы | `multipart/form-data` (`image`, `view_type`) | `202 Accepted` + задача обработки |
| GET | `/studies/{study_id}/images/{image_id}` | Скачивание снимка или результата анализа | header `Accept: image/png` или `application/json` | Бинарный файл или JSON маски |
| POST | `/studies/{study_id}/report` | Сохранение заключения | `{"findings": "...","recommendations": "...","confidence": 0.92}` | Возвращает pdf_url |

### Аналитика и мониторинг
| Метод | Путь | Описание | Параметры | Ответ |
| --- | --- | --- | --- | --- |
| GET | `/analytics/overview` | Сводка KPI по ролям | query `from`, `to`, `department` | Метрики для дашборда |
| GET | `/analytics/doctor/{doctor_id}` | Персональная статистика врача | query `from`, `to` | Кол-во исследований, SLA, топ диагнозов |
| GET | `/analytics/alerts` | Активные инциденты | query `severity` | Массив алертов |

### Системные эндпоинты
| Метод | Путь | Описание | Примечание |
| --- | --- | --- | --- |
| GET | `/health` | Проверка статуса сервиса | Используется мониторингом |
| GET | `/version` | Текущая версия сборки | Для UI оверлея |
| GET | `/config/ui` | Параметры темы и фич-флагов | Кэшируется на клиенте |

#### Общие требования
- Валидация ошибок: `400` — валидация, `401` — просроченный токен, `403` — недостаточно прав, `404` — не найдено, `409` — конфликт, `422` — неконсистентные данные.
- Для загрузки файлов принят предел 30 MB, остальные полезные нагрузки — до 1 MB.
- Все модифицирующие операции логируются с user_id, patient_id и IP.
- Данные пациентов передаются только по HTTPS, для on-premise — через внутренний VPN.
